# Ручное QA — волна 2_core (FEAT-FC-UX-001…009)

Предусловия: завершён `1_core` (posting roles, без литералов 101/221 в API оплаты/инвойсов). Пользователь с ролью ACCOUNTANT+, выбранная организация.

## UX-002 — блокирующий выбор компании

1. Пользователь с доступом к **двум** организациям, `organizationId` не задан.
2. Войти → модалка выбора компании, Escape / клик вне / крестик **не** закрывают.
3. F5 → модалка снова.
4. Выбрать org → модалка исчезает, в шапке отображается выбранная компания.

## UX-006 — RBP (prepaid)

1. `/finance/prepaid-expenses` — таблица, кнопка создания.
2. Создать запись с полем **description** → сохраняется, видна в списке.

## UX-008 — инвойс, денежные счета

1. Продажи → новый инвойс → список «Ödəniş hesabı» из `/api/system/money-accounts?purpose=incoming` (не только 101/221).
2. Выбрать банк → появляется выбор банковского счёта; валюта подставляется/блокируется по счёту.
3. Сохранить инвойс с `bankAccountId` для банковского варианта.

## UX-009 — оплата закупок

1. `/purchases` → меню строки → **Ödəniş et** → частичная оплата → долг 531 уменьшается.
2. `/finance/payables/suppliers` → та же модалка, оплата по контрагенту (FIFO на API).
3. Оба пути вызывают соответствующие `POST` endpoints purchases/payables.
