# ERA Construction — промо-бриф (сателлит + Finance + CRM)

**Статус позиционирования:** edition `mvp` · Demo/pilot open · **не заявлять GA / «готово к продаже как полный Procore»**.  
**Аудитория:** демо инвестору / заказчику / партнёру — «что уже умеет связка».  
**SSOT sell/show:** [`Construction-Product-Readiness-Matrix.md`](../acceptance/Construction-Product-Readiness-Matrix.md) · boundaries: [`construction-domain-boundaries.md`](../adr/construction-domain-boundaries.md).

---

## Слайд 1 — Одна фраза

**ERA Construction** — операционный контур стройплощадки, который живёт в одной экосистеме с **продажами (CRM)** и **деньгами (Finance)**, а не как отдельный «ещё один Excel / ещё один Procore».

> Лид → договор и оплаты → объект, смета, поле, акт → проводки и КС — без ручного переноса между тремя системами.

---

## Слайд 2 — Почему это не «ещё один строй-софт»

Исследование рынка (Procore, ACC, Oracle, Buildertrend, Fieldwire) показало одно ядро у всех лидеров и слабые места: закрытый API, грубые права, слабая локальная отчётность (КС), CRM только у жилого сегмента, финансы либо дорогие, либо поверхностные.

**ERA делает иначе:** не копирует монолит «всё в одном приложении», а **разносит контур по плоскостям** — и связывает их событиями:

| Плоскость | Что владеет | Для заказчика это значит |
|-----------|-------------|---------------------------|
| **CRM** | Лид → квалификация → визит → convert | Продажи и гарантийный цикл до стройки |
| **Finance** | Контрагенты, договоры, закупки, акты оплаты, КС-2/КС-3, GL/WIP | Юридические и бухгалтерские деньги |
| **Construction** | Объект, смета (BOQ), поле, чертежи, акты выполнения как ops-пакет | Работа ГП / прораба / ПТО на площадке |
| **Control Plane** | Доступы, entitlement, табель (SoR), найм персонала | Единый вход и кадры |

Деньги и CRM **не дублируются** внутри стройки — это преимущество для внедрения: бухгалтерия остаётся в Finance, продажи — в CRM.

## Слайд 3 — Сквозной сценарий (демо-нарратив)

```text
CRM: лид / selections / convert
        ↓  контрагент + коммерческий контур
Finance: договор · SOV · тендеры · PayApp · КС-2/КС-3 · WIP
        ↕  ссылка financeContractId / события
Construction: проект · BOQ · поле · акт с строками · change ops
        ↓  SATELLITE_CONSTRUCTION_PROGRESS_ACT_APPROVED
Finance: журнал (идемпотентно construction:{actId})
        ↕
CP: табель / staff login на площадку
```

**30-секундный питч:**  
«Клиент появляется в CRM, становится контрагентом и договором в Finance, объект ведётся в Construction; утверждённый акт сам попадает в учёт — без Excel-моста.»

---

## Слайд 4 — Что умеет Construction (площадка)

Готовый ops-контур на хабе проекта (`/projects/[id]`) и поле (`/field-ops`):

| Блок | Возможности |
|------|-------------|
| **Объект** | Проекты, участники (ГП / субподряд / заказчик), этапы и локации, VÖEN субподрядчика |
| **Смета и выполнение** | BOQ, план vs факт, строки акта (ops SOV), утверждение акта |
| **Поле** | Daily log (люди по сторонам, погода, работы), punch/замечания с пином на лист, инспекции → замечание |
| **Согласования** | RFI, submittals (в т.ч. Reject / REVISE), change request (ops); деньги по изменению — в Finance |
| **Документы** | CDE: ревизии листов, статус актуален / заменён |
| **График и ресурсы** | Gantt-задачи, часы техники, заявки на материалы, претензии/claims субподряда |
| **BIM lite** | Ссылки на IFC-элемент / внешний viewer на punch и RFI (SKU) |
| **Доступы** | Матрица ролей × прав (`/admin/access`), deny → `/access-denied` |
| **Кадры** | Найм в CP → логин в Construction; табель площадки → CP → зеркало в Finance |

## Слайд 5 — Что даёт Finance рядом со стройкой

| Возможность | Смысл для стройки |
|-------------|-------------------|
| **Договор + SOV + ContractAmendment** | Коммерческая правда; ops change может черновить amendment при `financeContractId` |
| **PayApplication** | Жизненный цикл платёжного / акта оплаты |
| **КС-2 / КС-3 print** | Локальные формы (снимок при APPROVED) — ниша, которую западные suite почти не закрывают |
| **Тендеры → draft Contract** | Закупки / сравнение предложений в коммерческом контуре |
| **Журнал по акту стройки** | `SATELLITE_CONSTRUCTION_PROGRESS_ACT_APPROVED` → WIP/выручка, идемпотентный ключ |
| **Закупки / контрагенты / оплаты** | PO и платежи не живут «внутри Excel прораба» |

## Слайд 6 — Что даёт CRM рядом со стройкой

Цикл Buildertrend-класса **разнесён честно**, без второй CRM внутри стройки:

| Возможность | Смысл |
|-------------|--------|
| **Лид → convert** | Авто-контрагент в Finance (`SATELLITE_CRM_LEAD_CONVERTED`) |
| **SelectionPackage** | Пакет отделки / выборов после convert (SKU) |
| **WarrantyCase** | Гарантийные обращения на карточке лида (SKU) |
| **Party / VÖEN / import** | Физлицо и юрлицо, импорт проспектов, сектор деятельности |

После convert объект и площадка ведутся в **Construction**; продажи и гарантия до/вокруг сделки — в **CRM**.

## Слайд 7 — Отличия от «купить Procore / Buildertrend»

| Тема | Типичный рынок | ERA |
|------|----------------|-----|
| CRM + стройка + бухгалтерия | Либо нет CRM, либо слабый GL, либо три вендора | Одна экосистема, чёткие границы плоскостей |
| Локальные акты | Слабо / нет КС | КС-2 / КС-3 в Finance + ops-акт в Construction |
| Права | Часто грубые | Матрица ролей × модуль на сателлите |
| Интеграции | Marketplace / закрытый API | Доменные события в шину оркестратора уже сейчас |
| Цена / внешние участники | Дорого / плата за место | Модель entitlement по модулям экосистемы (не монолит ACV) |

## Слайд 8 — Честные рамки (обязательно в демо)

Говорить можно:

- «Связка Construction + Finance + CRM на MVP: сквозной сценарий от лида и договора до акта и журнала.»
- «Поле, смета, CDE-ops, RFI/punch, график, claims — на экранах хаба проекта.»
- «Локальные КС и коммерческий договор — в Finance, не в Excel.»

Не говорить:

- «GA / полный коммерческий ABS / готово к полевому пилоту без оговорок» — Pilot lab/field ещё open, edition `mvp`.
- «Полный Procore / ACC / Oracle в одном приложении».
- «SHARED multi-tenant Construction pool как продаваемый факт» (AC tenancy 🟡).
- «Публичный Open API / webhooks как отдельный продукт» — шина событий есть; customer-facing webhook product = отдельное решение.

## Слайд 9 — Demo script (8–10 минут)

1. **CRM (2 мин):** лид → convert → показать контрагента / selections или warranty на карточке.  
2. **Finance (3 мин):** договор + SOV; при наличии — PayApp / печать КС; тендер → draft contract (если SKU).  
3. **Construction (4 мин):** открыть проект → BOQ / строки акта → approve; daily log + punch на лист; RFI или change; вкладки structure / schedule / claims.  
4. **Связка (1 мин):** показать, что утверждение акта уходит событием в Finance (журнал / meta), а не копируется руками.

## Слайд 10 — Закрывающая формулировка

**ERA Construction** — это не «замена Excel на сайте».  
Это **операционная стройка**, встроенная в **продажи и учёт** той же платформы: CRM закрывает сделку, Finance держит деньги и КС, Construction ведёт объект и поле — с событиями между ними.

*Для внутреннего использования: при обновлении фич сверять этот бриф с Product-Readiness и COVERAGE; не разгонять Sell выше худшего слоя матрицы.*
