## 5. Новые дефекты в свежем коде

Регресса закрытых пунктов нет.

### 5.1 `GET /api/tasks` по-прежнему отдаёт все orphan-задачи организации

`integrations-routes.ts` 646–654:

```ts
OR: [
  { leadId: null },
  { lead: leadWhere },
  { assigneeId: String(userId ?? "") },
],
```

`{ leadId: null }` не ограничен scope (в отличие от conversations/calls). Агент с scope `group`/`own` видит заголовки всех безалидных задач тенанта. Complete для orphan уже закрыт; list — нет.

### 5.2 Funnel: среднее время в стадии игнорирует `pipelineId`

`integrations-routes.ts` 819–826 фильтруют `groupBy` history по `lead.pipelineId`, но `recentHistory` (851–855) берётся с `where: { organizationId }` без этого фильтра. При выборе воронки `avgHoursInStage` смешивает чужие пайплайны. N+1 снят, это новая неточность в том же хендлере.

### 5.3 Смена стадии через `stageId` обходит `validatePartyForStage`

`nest/generated/leads__id_stage.ts` 50–57: путь `pipelineStageId`/`stageId` сразу зовёт `moveLeadToPipelineStage` и возвращает результат. Проверка `validatePartyForStage` есть только на ветке `body.stage` (строки 60–62). Перевод на kind/legacy `WON` с канбана может обойти партийный гейт.

### 5.4 `createInboxThread` может привязать тред не к тому коннекту

`inbox.service.ts` 88–96: в `OR` всегда попадают `whatsapp_cloud` и `instagram`, сортировка `createdAt: asc`. POST `/api/inbox` с каналом Instagram при более старом WhatsApp-коннекте запишет Conversation на WhatsApp.

### 5.5 Прочее (остатки, не регресс)

- `/challenge`: 200 vs 404 всё ещё оракул включённых `publicId` (см. §2).
- Captcha burn / rate limit — только in-process Map.
- `convertLeadWon` не вызывает `applyAllPipelineRules` и не двигает `stageId`.
- S1: non-prod без секрета; HMAC fallback на `JSON.stringify`.

Сломанных импортов/типов в изменённых файлах не видно. UI бьёт в существующие эндпоинты: `/api/pipelines`, `PATCH /api/pipelines/:id/stages/:stageId`, `PATCH /api/leads/:id/stage` с `{ stageId }`, `/api/tasks/:id/complete`.
