## 5. Новые баги (регрессии / свежие дефекты)

Не откатывают закрытые пункты, но их нужно чинить.

1. **`purgeInboundRawBodies` обращается к несуществующему полю.** В `outbox.worker.ts`: `where: { createdAt: { lt: cutoff } }`. У `InboundEvent` в схеме поле `receivedAt`, не `createdAt`. Cron раз в 6 часов упадёт (Prisma unknown argument).
2. **Запасной путь outbox: `orderBy: { createdAt }` у `Message`.** У `Message` есть `sentAt`, нет `createdAt`. Основной путь с `payload.messageId` в порядке; fallback при отсутствии id сломается.
3. **Двойной drain outbox при `REDIS_URL`.** `startOutboxWorkerLoop` одновременно крутит `setInterval` и BullMQ Worker, оба зовут `processOutboxBatch`. Смена статуса на `SENDING` **не атомарна** (`findMany` PENDING → `update` по id без `status: PENDING`). Возможен двойной send. Inbound защищён лучше (`updateMany` RECEIVED→PROCESSING).
4. **`POST /api/calls/originate` не проверяет, что `connectionId` принадлежит текущему `organizationId`.** Чужой id коннекта (если угадать) создаст outbox в чужом соединении.
5. **Challenge без `hub.mode`/`hub.verify_token`.** В `_factory.ts` проверка токена только если `mode === "subscribe" || token`. Запрос с одним `hub.challenge` получает 200. Meta так не ходит, но универсальный challenge снова открыт.
6. **Секрет виджета в URL.** `widget.js` кладёт webhook secret в `?k=` и в атрибут скрипта — утечка в логи прокси и Referer.
7. **Документационный регресс плана.** `.cursor/plans/crm-integrations-full.plan.md`: все волны, включая I-4, P0 record-level scope и acceptance, помечены `status: completed`. Это не соответствует коду (P0-7, orch WA, SSE UI, UAT «not SHIPPED»).
