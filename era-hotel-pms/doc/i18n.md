# UI internationalization (i18n)

Stack: [next-intl](https://next-intl.dev) + [`@era/i18n-common`](../../packages/i18n-common) · locales **az**, **ru**, **en** (UI order AZ → RU → EN).

## Behaviour

- Language is stored in cookie **`era_i18n_lang`** (`path=/`, 1 year, `SameSite=Lax`).
- Legacy cookie **`NEXT_LOCALE`** is still read for one release and written on switch.
- Switcher: `LocaleToggle` / `LanguageSwitcher` on **Login** and **AppNav**; `POST /api/locale` `{ "locale": "az" }`.
- **Default locale: `az`** (`DEFAULT_LOCALE=az` in `.env` optional).
- **Fallback:** `messages/az.json` is merged first; `ru.json` / `en.json` overlay missing keys (see `createNextIntlRequest` in `@era/i18n-common`).

## Adding strings

1. Add keys to `messages/az.json` (source of truth), then partial `ru.json` / `en.json`.
2. Client: `const t = useTranslations('namespace');`
3. Server / metadata: `getTranslations('namespace')` from `next-intl/server`.

## Coverage

All routes under `app/**/page.tsx` should use message files. API error strings may remain English.
